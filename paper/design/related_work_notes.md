## 2. 우리 설계의 각 요소를 받치는 문헌

**소액 자동 처리(STP)와 임계값 회피**
- 🔴 [Claims Journal 2019](https://www.claimsjournal.com/news/national/2019/08/02/292316.htm): 보험사는 전문가 심사 비용보다 지급액이 적은 금액 미만 청구에 STP를 적용하고, 사기는 **상한 바로 아래로 쪼갠 허위 청구 여러 건**이나 **상한까지 부풀린 청구**로 이를 노린다고 설명. → 우리 A4(분할 청구)의 실무적 근거. 학술 근거는 아님.
- 🔴 "STP 누수 약 15%" 같은 수치는 벤더 블로그 주장이며 검증 불가. 인용하지 말 것.
- **빈 곳:** 임계값별 자동화율·누수를 실측·정량화한 학술 연구는 찾지 못했다. (우리 기여 후보)

**사람에게 넘기는 정책(deferral)과 분류-연기**
- 🟢 [DeCCaF, Alves 외(Feedzai), TMLR 2024, arXiv 2403.06906](https://arxiv.org/html/2403.06906v3): 비용 민감 learning-to-defer, 사람의 작업량 제약 반영, 사기 경보 검토에 적용. → 우리 임계값 스윕을 **"작업량 제약 아래 비용 최소 연기 정책"**으로 정식화할 방법론적 근거.
- 🟡 [Mozannar & Sontag 계열, arXiv 2006.01862](https://arxiv.org/pdf/2006.01862) (검색 요약 기준, 제목 확인 필요), [Top-k L2D, arXiv 2504.12988](https://arxiv.org/html/2504.12988v4): 선택적 예측과 연기.

**LLM 권고에 대한 사람의 반응(자동화 편향)**
- 🟢/🟡 [Deciding Fast and Slow, arXiv 2010.07938](https://arxiv.org/pdf/2010.07938), [Limits of Interventions in AI-Assisted Decision Making, AIES](https://ojs.aaai.org/index.php/AIES/article/view/43309), 설명이 오히려 편향을 키울 수 있다는 2026년 연구, 보상 구조가 과의존을 줄인다는 2025년 연구(180명). → **권고가 정확해도 사람이 맹신할 수 있고 개입의 효과는 제한적**이라는 맥락. 우리가 사람 실험을 못 하는 이유를 한계가 아니라 "알려진 위험, 그래서 보정 지표를 함께 제시"로 설명할 근거.

**근거 부족 시 LLM의 행동**
- 🟡/🔴 [Google Research, "sufficient context", ICLR 2025](https://research.google/blog/deeper-insights-into-retrieval-augmented-generation-the-role-of-sufficient-context/): 근거가 불충분할 때 모델이 기권하지 않고 답해 오답이 늘어남(보고서 기준 Gemma 10.2%→66.1%). [GRAB-RAG, AACL 2026](https://aclanthology.org/2026.aacl-long.153.pdf): 근거가 없을 때는 기권하지만 오도하는 근거에는 41.6% 답함. → 우리 **현행 요약(날짜·코드 없음)** 조건에서 LLM이 "근거 부족"이라 하지 않고 정상으로 답할 것이라는 가설(H2)의 근거. **"근거 부족" 판정 선택지를 추가**해야 하는 이유.

**신뢰도 보정**
- 🟡 [Calibrating Expressions of Certainty, arXiv 2410.04315](https://arxiv.org/pdf/2410.04315), [ConfTuner, arXiv 2508.18847](https://arxiv.org/html/2508.18847v2), AFCE(ACL Findings 2025): 말로 표현한 신뢰도는 대체로 과신, 프롬프트로 개선 가능. → 우리 ECE/Brier 측정과 일치, 구조화 출력의 신뢰도 필드 정당화.

**프롬프트 인젝션**
- 🔴 [Taktile PIBench, 2026-06](https://labs.taktile.com/benchmarks/pibench): 에이전트 언더라이팅 대상 인젝션 53건(자유 텍스트 메모, 구조화 필드, PDF 등), GPT 계열 평균 방어 99.6%, Gemini 85.3%. **벤더 보고 수치.**
- 🟡 [AgentDojo, arXiv 2406.13352](https://arxiv.org/pdf/2406.13352), FinVault(금융 에이전트 보안 벤치마크, 963건): 일반·금융 에이전트 인젝션 평가. 보험 사용 사례 목록(2026-04 초안)은 **청구 접수 텍스트가 주요 주입 경로**라고 지적.
- → 우리 A6/U5(청구 설명·청약자명 인젝션)는 이 흐름과 일치. 인젝션 사례 수가 적다(5건·6건)는 약점이 있으니 확대 필요.

**LLM이 데이터 원천을 믿는 문제(오라클)**
- 🔴 AI 오라클 가이드·블로그, 🟡 C-LLM(노드 합의): 오프체인 데이터의 진위는 블록체인이 검증하지 못한다는 **오라클 문제**. → **중요한 구분:** 온체인에서 생성된 이력(납입, 청구 상태)은 무결성이 보장되지만, 치료 설명·병원 기록처럼 오프체인에서 들어오는 입력은 보장되지 않는다. 우리 RQ3의 주장 범위를 "온체인 생성 근거"로 한정해야 한다.

**LLM 보험 청구 연구 일반**
- 🟡 2026 리뷰: 사람 검토를 **언제 발동시킬지**와 자동 처리·전문가 검토의 역할 정의에 대한 연구가 더 필요하다고 지적. → 우리 질문과 정확히 맞는 빈 곳(리뷰 원문 확인 필요).
- 🟡 [Gender Bias in LLM-Evaluated Insurance Claims, CRA 2026](https://media.crai.com/wp-content/uploads/2026/07/29155621/Beyond-the-Binary_-Gender-Bias-in-LLM-Evaluated-Insurance-Claims.pdf): 실제 청구에는 객관적 정답이 없다(결과가 한 명의 심사자 판단)는 점을 지적. → **우리처럼 정답을 구성하는 설계의 정당화**, 그리고 **공정성(반사실 검사)**이라는 확장 주제.
- 🔴 ResearchGate 게시 연구들(심사자 만족도, 50,000건 파이프라인, 심사자 300명 무작위 시험 언급): 방법론 확인 불가. 인용 전 원문 검증 필요.

## 3. 빈 곳과 우리의 위치 (검색 범위 안에서)

1. 소액 자동 처리의 **임계값-누수-작업량 trade-off를 정량화한 연구**: 실무 글만 찾음.
2. **LLM 권고 품질이 입력 근거 수준에 좌우되는 정도**를 보험 심사에서 측정한 연구: 일반 RAG 연구는 있으나 보험 심사 특화는 찾지 못함.
3. **블록체인 근거와 변조 가능한 근거 아래의 LLM 심사 비교**: 블록체인+LLM 사기 탐지(Islayem 2025)는 있으나 근거 무결성 비교는 찾지 못함.
4. **자동 처리/LLM 권고의 경계(언제 사람을 부를지)**: 2026 리뷰가 빈 곳으로 지목.

## 5. Islayem et al. (2025) 정독 결과 — 우리와의 차이

**읽은 범위:** PMC 본문 전체(서론~결론). 그림(채팅 캡처)과 GitHub 저장소(`rubak3/InsuranceFraudDetection`)는 보지 않았다. 아래 "본문에서 못 봤다"는 표현은 내가 읽은 본문 기준이다.

**시스템:** 이더리움 스마트컨트랙트 3개(Registration, MedicalRecords, InsuranceClaims), 비정형 문서는 IPFS, Etherscan API로 거래 조회, OpenAI Assistant(GPT-4o)+file search(RAG)+function calling, Sepolia 테스트넷 배포. 새 청구 이벤트마다 LLM이 **이진 출력(1=사기, 0=정상)**을 내고, "최종 결정은 보험사 심사자에게 남긴다". 챗봇이 지갑 서명을 거쳐 승인·거절 컨트랙트 함수를 호출할 수도 있다.

**평가:** 직접 만든 합성 청구 **100건**(정상+사기, 중복 청구·금액 부풀리기·미제공 서비스·불필요 시술/약), GPT-4o·Gemini 1.5 Pro·Claude 3.5 Sonnet을 JSON으로 호출. Table 2: GPT-4o 정확도 99%, 정밀도 100%, 재현율 98.4%, F1 99.2%, 사기 유형 분류 97% / Gemini 98·100·96.9·98.4·96 / Claude 97·100·95.3·97.6·95. 공개 Kaggle ICU 입원 데이터 1,425건(특성 30개, 과잉 치료 탐지)에서 95.8%, 비교 대상은 **다른 논문이 같은 데이터에서 보고한 랜덤 포레스트 88.31%**(같은 프로토콜로 직접 돌린 비교가 아님). 시나리오 6개 전부 탐지, 실시간 탐지 12.94초, 청구당 비용 약 $0.03 미만, Slither 정적 분석 "취약점 없음".

**내가 역산한 것(논문에 명시 안 됨):** 재현율 98.4/96.9/95.3%는 각각 63/64, 62/64, 61/64이고 정확도·정밀도 100%와 정확히 맞아떨어진다 → **사기 64건 + 정상 36건, 오탐 0건**으로 보인다. 즉 사기 비율이 약 64%인 농축 표본이고 반복 횟수·신뢰구간·통계 검정은 본문에서 못 봤다.

**겹치는 점:** 블록체인+LLM+보험 청구, 사람이 최종 결정, GPT-4o 사용. 컨트랙트가 일부 사기를 LLM 없이 막는다는 설계(`claimRequested` 플래그로 중복 청구 차단, 청구액이 서비스 비용을 넘으면 거부)는 우리의 "결정론적 계층" 원칙과 같은 방향이다. **우리 컨트랙트에는 이런 내용 검증이 없다** — 소액 자동 지급이 금액 한도만 본다는 우리 발견과 대비되는 점이니 한계·향후 과제에 쓸 수 있다.

**우리가 다른 점(본문 기준):**
| | Islayem 2025 | 우리 |
|---|---|---|
| 질문 | LLM이 사기를 얼마나 잘 탐지하나 | **어디까지 자동으로 맡기고 어디부터 사람에게 넘기나**(누수·작업량), 권고 품질 |
| 자동화 경계 | 모든 청구에 LLM 플래그, 임계값·소액 자동 지급 분석 없음 | 소액 자동 지급 + 고액 권고, 임계값 스윕, 연기 정책 프런티어 |
| 근거 | 전체 온체인·IPFS 맥락을 RAG로 제공, 근거 수준 비교 없음 | **근거 수준(현행 요약 vs 상세) 비교**, "근거 부족" 판정 |
| 무결성 | 불변성을 주장, 변조 실험 없음, 기존 DB와의 비교 없음 | **변조 가능한 DB와 체인 비교**, 변조 시 권고 변화 측정 |
| 지표 | 정확도·정밀도·재현율·F1, 단일 실행 | 누수율, 작업량, **보정(ECE/Brier)**, 기권률, 반복·신뢰구간 |
| 적대적 입력 | 인젝션·자유 텍스트 위험 논의 못 봄 | 설명·이름 필드 인젝션 평가 |
